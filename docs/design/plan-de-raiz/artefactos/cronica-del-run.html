La crónica del run

Una sola derivación de "qué pasó", en el vocabulario en que el frame ya dice "dónde está". Las superficies dejan de elegir palabras: la región, el scrollback y las líneas append-only disponen las mismas.

Lo que hay hoy

El CLI presenta un run desde dos derivaciones distintas que no se conocen entre sí.

Tres textos afirman una unidad que ningún mecanismo sostiene: el rustdoc de lines.rs ("it is the same content the pinned region carries"), el de render::state ("the vocabulary every surface says it in" — y lines.rs no lo importa), y D162 ("el mismo contenido sale como líneas append-only, una por evento"). Según CLAUDE.md la documentación gana: hay una divergencia declarada.

Y se paga. En el merge de main, lines.rs tuvo que crecer cinco brazos —FindingUpdated, FindingWithdrawn, FindingRefused, ArtifactSubmitted, ArtifactAccepted— mientras el frame los absorbía por otro camino. Y el defecto que corregí en esta rama (un nodo que vuelve a correr y cuyo éxito nunca reaparecía arriba) vive en Scrollback::gone: memoria que existe solo porque el scrollback deduce "qué cerró" comparando dos frames en vez de leerlo del log.

El principio

El log es una secuencia de eventos; una persona lo lee como una secuencia de hechos. El engine deriva el frame (dónde está cada cosa) y la crónica (qué pasó, en orden) del mismo log y con los mismos tipos. El CLI elige las palabras una vez por hecho; cada superficie solo las dispone. Lo que un frame dice que un nodo es, la crónica dice que se volvió. Es el mismo NodeState, y NodeDisplay lo nombra una sola vez.

La derivación

Un módulo hermano de view/node.rs y view/phase.rs: crates/engine/src/view/chronicle.rs. Misma familia que derive y run_frame — función pura del log, sin reloj, sin storage, sin saber con qué se dibuja.

// crates/engine/src/view/chronicle.rs

/// One thing that happened to a run, placed: when, to which node, and
/// what. The chronicle's unit, derived from the log the way a frame is
/// and in the same types — what a frame says a node *is*, a moment says
/// it *became*.
pub struct Moment {
    pub seq: Seq,
    pub at: DateTime<Utc>,
    /// The run's own clock at this point: from its first event to this
    /// one. What a reader after the fact places the moment by.
    pub elapsed: Duration,
    /// The node it concerns, `None` for a run-level moment.
    pub node: Option<NodeId>,
    pub happening: Happening,
}

/// What happened, read as a person reads it. Every arm carries the type
/// the frame already holds for the same fact, so no surface can say one
/// thing about a state and another about the moment it was reached.
pub enum Happening {
    // — the run
    RunCreated { mode: ModeName, base_branch: String },
    RunPaused { reason: String },
    RunResumed,
    RunClosed { terminal: TerminalState, tokens: TokenUsage },
    PromotionSignaled { to: ModeName, reason: String, evidence: Evidence },

    // — a node
    RunnerResolved(ResolvedRunner),
    /// The node reached `state` — started, finished or failed. A node
    /// that settles carries how long it worked and the children it bore,
    /// because they leave the region with it.
    Node { state: NodeState, elapsed: Option<Duration>, children: Vec<ChildLink> },
    Rerouted(Reroute),
    /// A question put to a person: the escalation as `gate_waiting`
    /// recorded it, which is what the demand line and the closing block
    /// already read.
    Escalated(GateWaitingPayload),
    GateResolved(GateResolvedPayload),
    QuestionsAnswered { channel: Channel, responder: Option<Responder> },
    LoopIteration { iteration: u32 },
    HookRan { phase: HookPhase, exit_code: i32 },
    ContextAssembled,
    BaselineCaptured,

    // — a session
    SessionOpened(OpenSession),
    /// A tool the session reached for — the same reading `NodeFrame::activity` shows live.
    Called(ToolCall),
    Message(AgentMessageType),

    // — the tasks document
    TaskRegistered { task: TaskId },
    TaskMoved { task: TaskId, to: TaskStatus },
    CriteriaChecked { task: TaskId, phase: Phase, checked: usize },

    // — scope
    ScopeChecked { violations: usize },
    ScopeExpansion { task: TaskId, step: ScopeExpansionStep },

    // — findings and artifacts
    Finding { id: FindingId, severity: FindingSeverity, title: String, change: FindingChange },
    ArtifactSubmitted { kind: ArtifactKind, name: String, taken: bool },
    ArtifactAccepted(ArtifactId),
    ArtifactWritten { path: PathBuf },

    // — composition and capability
    ChildBorn(RunId),
    ChildClosed { run_id: RunId, terminal: TerminalState },
    Degraded(Degradation),

    /// A kind this binary does not know. It is still a moment: a reader
    /// who is not told the log carries more than the binary reads is a
    /// reader misled.
    Unknown { kind: String },
}

pub enum ScopeExpansionStep { Requested { paths: Vec<String> }, Granted { by: Decider }, Denied { by: Decider, reason: Option<String> } }
pub enum FindingChange { Posted, Updated, Withdrawn { reason: String }, Refused { operation: FindingOperation, problems: usize } }

/// Reads the log as the sequence of moments a person met it as: one per
/// event, in the log's order, each placed by the run's own elapsed.
///
/// Pure, and monotone in the log: the chronicle of a prefix is a prefix
/// of the chronicle. That is what lets a surface remember how many it
/// has written and write the rest, and never reprint one.
pub fn chronicle(events: &[StoredEvent]) -> Vec<Moment>

Tres invariantes, todos testeables

  • Uno por evento. chronicle(events).len() == events.len(), con Unknown incluido. Es D162 tal como está escrito: "una por evento".
  • Monótona en el log. Para todo n, chronicle(&events[..n]) es prefijo de chronicle(events). Es lo que hace correcto el contador written que el pintor ya tiene, y lo que hace que un momento nunca se reimprima.
  • El frame concuerda con la crónica. Para cada nodo, frame.nodes[n].state es lo que dice el último momento sobre n: Node{state} → Reached(state); Escalated → Reached(Waiting{..}); ninguno → ToGo o Skipped. Y frame.reroutes es la cuenta de Rerouted, frame.degraded son los Degraded, frame.children los ChildBorn/ChildClosed.

El tercero es el que ata las dos derivaciones. No se implementa el frame como fold de la crónica —run_frame ya tiene su camino por derive y stats— pero el test dice que no pueden discrepar, y los tipos compartidos hacen que discrepar sea difícil de escribir.

Qué necesita la derivación, y por qué no es "un match sobre el payload"

Casi todo momento es una lectura del evento solo. Tres cosas necesitan el prefijo: el elapsed del run (primer evento), el elapsed del nodo que cierra (su node_started), y los children de un nodo que cierra (sus child_run_created/_finished anteriores). Por eso chronicle toma el log y no un evento: un pase O(e) con un estado mínimo, del mismo orden que derive. El pintor la rederiva en cada pase sobre folded.settled(), igual que hoy rederiva run_frame — la pureza vale más que el ahorro, y el costo es una fracción del que ya se paga.

Dos filas merecen una palabra. run_created nunca se escribe hoy tampoco: el pintor pliega la semilla sin escribir una línea por ella (Painter::attach_to), porque es lo que el run ya era y no lo que esta invocación hizo; la crónica conserva eso tal cual. run_finished no se conserva arriba de la región porque el bloque de cierre es su registro en una terminal — una línea + run — finished justo encima de run 01J…: + finished diría lo mismo dos veces; en el modo append-only sí sale, porque ahí el bloque de cierre llega por stdout y la crónica por stderr.

Las palabras

Un módulo hermano de surface/view.rs: surface/chronicle.rs. Donde view.rs elige una vez las palabras de un frame, este elige una vez las de un momento — y las dos pasan por render::state::NodeDisplay para todo lo que es un estado.

// crates/cli/src/surface/chronicle.rs

/// One moment as a surface says it, before any layout decides where
/// it goes: the mark for the eye, and the sentence for everybody.
pub(super) struct Said {
    /// The state the moment reaches, when it reaches one — what the
    /// glyph beside the line stands for. `None` for a moment that is
    /// not a state: a call, a task moving, a hook.
    pub(super) word: Option<StateWord>,
    /// `subject — what happened`, one line, already collapsed.
    pub(super) text: String,
}

/// The words for `moment`. One match, and the only one: a kind that
/// earns new words earns them here for every surface at once.
pub(super) fn say(moment: &Moment) -> Said

/// Whether a terminal a person is watching keeps `happening` above its
/// region once it has scrolled past. What closes something, or asks
/// something of a person, is kept; what is in flight is shown live in
/// the region and not kept. The append-only surface keeps everything:
/// a reader who arrives after the fact has no region to have watched.
pub(super) fn kept(happening: &Happening) -> bool

/// The rows a settled node leaves behind: its own line, and the
/// children it bore indented under it — a tree, as the region drew it.
pub(super) fn graduation(moment: &Moment, glyphs: Glyphs) -> Vec<String>

La forma de toda oración es la que yunta_core::text::aside ya fija: sujeto — lo que carga. Para un nodo que alcanza un estado, "lo que carga" es exactamente NodeDisplay::of(state).label() — la misma cadena que hoy imprime la graduación del scrollback y yunta status. Eso es lo que hace que las tres superficies digan lo mismo por construcción y no por disciplina.

Lo marcado es la misma cadena, byte a byte, en las dos superficies. La izquierda conserva lo que cerró y muestra lo abierto en la región; la derecha conserva todo porque no tiene región. Lo que difiere es disposición: el prefijo [elapsed] de la derecha, y el árbol de hijos bajo un nodo que cierra a la izquierda. Nótese que el nodo lint corre dos veces y aparece dos veces arriba, con dos resultados distintos: no hay gone que olvidar, porque un nodo que cierra dos veces son dos momentos.

Las disposiciones

Cada superficie queda reducida a lo que le es propio: dónde va la oración y qué se le pone adelante.

Lines
moment(&Moment) escribe [elapsed] {glyph} {text}, para todo momento. open(out, reason) y note(line) siguen iguales. Desaparecen detail, resolution y counted_problems — sus 36 brazos son ahora chronicle::say. Queda en ~50 líneas.
Scrollback
Se queda con over(region, out) y write(lines): la única puerta hacia arriba, con la región fuera de pantalla mientras escribe. Desaparecen gone, leaving y restart: el scrollback ya no deduce qué cerró comparando frames, lo lee de la crónica. Queda en ~40 líneas.
Region
show(frame, run_id, answerable) dibuja lo abierto, como hoy. graduate(frame) pasa a ser record(lines) — recibe filas ya dichas y las manda arriba. restart() desaparece: la región no tiene memoria por run; demand, body y counters se reconstruyen en cada show.
view.rs
Pierde graduation, settled_nodes y working_nodes. Conserva demand_line, node_rows, child_row, children_by_node, counter_line, working y closed_as — que chronicle.rs consume para RunClosed y ChildClosed, como lines.rs ya lo consumía.
Closing · status · --json · MCP
Sin cambios: leen el frame. El bloque de cierre sigue siendo el registro del run en una terminal.
Turns · Feed · Fold
Sin cambios. La cortina sigue gobernando cuándo se escribe; el feed sigue siendo el observer; Folded sigue siendo el prefijo contiguo del que ambas derivaciones parten.

El pase del pintor

La única secuencia con orden que importa. Un pase de Painter::take, tal como queda:

  1. absorb(events) pliega los eventos del run en Folded y sigue a un sucesor de promoción si aparece — sin cambios.
  2. write_settled(): let moments = chronicle(folded.settled()); para cada m en moments[written..], draw.record(&m). Draw::Lines escribe cada uno; Draw::Live escribe los que kept admite, como graduation(m, glyphs), vía Region::record. Luego written = moments.len(). Bajo la cortina no escribe nada, igual que hoy: lo que se debe se cuenta, no se encola.
  3. redraw(): run_frame(folded.settled()) → region.show. Sin cambios.

Tres detalles que quedan resueltos por el mismo mecanismo:

  • attach_to(seed) sigue haciendo written = folded.settled().len(): por el invariante uno-por-evento es exactamente chronicle(seed).len(), así que un resume no reimprime el log — la garantía que esta rama ya tiene, ahora sostenida por un invariante y no por una coincidencia de conteo.
  • follow(successor) resetea written = 0 y Folded, como hoy; la llamada a region.restart() se va con el método.
  • El pintor recibe glyphs de SurfaceEnv — hoy los tiene solo la región. Es el mismo valor, leído una vez por la invocación.

Decisiones a registrar

Una ADR nueva y dos revisiones. El texto va acá completo para que la decisión se tome sobre lo que quedaría escrito.

D164 — El run se lee como una crónica derivada, y cada superficie la dispone. El engine deriva del log, junto al frame, una crónica: un momento por evento, en el orden del log, en los mismos tipos que el frame usa para decir dónde está cada cosa (NodeState, Reroute, ChildLink, Degradation, ToolCall, OpenSession, ResolvedRunner). Es pura y monótona en el log: la crónica de un prefijo es prefijo de la crónica. El CLI elige las palabras de un momento una sola vez, con el mismo vocabulario de estados que el frame, y cada superficie solo las dispone: la región dibuja del frame lo que está abierto; el scrollback conserva de la crónica lo que cerró algo o pidió algo a una persona; la superficie append-only escribe todos los momentos, cada uno con el tiempo del run adelante. Un test de propiedad sostiene que el frame concuerda con la crónica, y otro que lo que una terminal observada conserva es lo que la superficie append-only escribe. Racional: dos derivaciones con dos vocabularios se pagan dos veces por cada kind nuevo y divergen sin que ningún test lo diga; y un scrollback que deduce "qué cerró" comparando frames necesita memoria por nodo, que es donde vivió un defecto real. Descartados: hacer que el modo append-only dibuje frames (un frame no es una línea, y un lector después del hecho quiere el orden); declarar las dos superficies deliberadamente distintas y corregir D162 (barato, pero deja dos vocabularios sin nada que los ate); un --format json como salida de máquina (queda habilitado por el tipo, no lo reemplaza).

D162
Nota de revisión: "Revisada por D164: el contenido común es la crónica derivada; una terminal conserva lo que cerró y muestra lo abierto en la región, y sin terminal salen todos los momentos."
D45
Nota de revisión: la superficie viva presenta dos derivaciones puras, frame y crónica, ambas del log.
Contrato §8.5
La oración "sin terminal … el mismo contenido sale como líneas append-only, una por evento" pasa a: "sin terminal … la crónica sale entera como líneas append-only, una por evento; sobre una terminal, lo que cerró sube al scrollback con las mismas palabras y lo abierto vive en la región".
README
Las dos filas de la tabla de comandos (run, resume) dicen "the same content arrives as one line per event"; pasan a "every moment of the run arrives as one line, in the words the live view uses".
glosario
Entradas frame y crónica / momento, con la relación entre ambos en una oración.

paso 2 · lo que decide el humano

Qué conserva una terminal observada. La columna kept de la tabla es una propuesta: lo que cierra algo o pide algo a una persona. La arquitectura hace que la decisión viva en un solo match (chronicle::kept) y que cambiarla sea un brazo; no la toma. Tres lecturas posibles: (a) la propuesta; (b) además las tareas que se mueven (TaskMoved) y los artifacts aceptados, para un run largo de loop donde el nodo no cierra en minutos; (c) solo nodos que cierran, como hoy. Recomiendo (a): un nodo loop largo ya muestra sus tareas corriendo en la región, y lo que un lector quiere reencontrar arriba es lo que cambió el rumbo del run.

Nombres

Layout::aside → Layout::advice. yunta_core::text::aside nombra una forma tipográfica (sujeto — lo que carga) y la crónica la usa en cada línea; el método del trailer nombra qué puede hacer el lector, y ese concepto ya tiene nombre en el CLI: el módulo commands::advice (advice::resume, advice::parked_on). La palabra que se mueve es la que estaba usando el nombre ajeno.

Moment y Happening. El envoltorio y el hecho, como NodeFrame y NodeStanding: el frame es "el run en un instante"; un momento es "un instante en que algo pasó". Fact queda para la evidencia, que ya lo usa.

Retiro una objeción. Dije que Evidence::lines() en core::events era presentación fuera de lugar. No lo es: Failure es Display en el mismo módulo ("the prose a reader sees is produced from this, so no surface can disagree with the facts behind it"), y D133 pone en core::text cómo se ve un problema. Evidence::lines() sigue esa regla; se queda.

Lo que no cambia y lo que queda afuera

queda habilitado, no hecho

  • yunta log <run>: la crónica de un run terminado, con las mismas palabras. Es chronicle(events) más la disposición de Lines; no entra en este PR.
  • --json con la crónica como array de momentos versionado, para tooling. El tipo ya está; el schema publicado es una decisión aparte.
  • MCP workflow_status con "los últimos N momentos" para un agente que sondea. Misma derivación, otra disposición.

fuera de alcance, y a propósito

  • Checkout lo usan 3 de 19 archivos de test del CLI; los otros 16 arman el repo con init_repo + write. Es una migración mecánica y propia; el test pty-vs-pipe nuevo usa Checkout y no espera a esa migración.
  • Un pase incremental de la crónica (un Chronicler que pliega de a un evento). La rederivación por pase es O(e) y ya se paga O(n·e) por el frame; se mide antes de optimizar, y el invariante de prefijo garantiza que un incremental daría lo mismo.

Costo, sin adornos: dos módulos nuevos (~250 líneas de engine con sus tests, ~200 de CLI), cuatro archivos que se achican, seis tests nuevos de los cuales dos son de propiedad, una ADR y cuatro textos. Es un PR propio que arranca cuando feature/improve-ux esté mergeado, y el primer commit es la decisión de kept registrada en D164 — el paso 2 antes del paso 3.
