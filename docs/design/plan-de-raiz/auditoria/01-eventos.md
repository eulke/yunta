## 5. WIRE FORMAT CONSTRAINTS

**Tagging.** `#[serde(tag = "kind", rename_all = "snake_case")]` on `EventPayload` (`mod.rs:284`) — internally tagged, one flat object per event.

**Envelope.** `StoredEvent` has **hand-written** `Serialize` (`mod.rs:217-238`), `Deserialize` (`:240-263`) and `JsonSchema` (`:265-280`). The reason is stated at `:201-203`: *"serde's own `flatten` cannot fall back to an unknown kind."* Serialization builds the `Envelope` object then `object.extend(body.to_object())`; deserialization pulls the five envelope keys out by name (`:246`) and hands the remainder to `EventBody::from_object`.

**Tolerance for newer writers.** `EventBody::from_object` (`mod.rs:167-183`) decides by **`KINDS` membership, not by serde failure**:
- kind ∈ `KINDS` → `serde_json::from_value` into `EventPayload`; a mis-shaped known kind is a hard `EventShapeError::Payload`, never an `Unknown` (`:176-179`).
- kind ∉ `KINDS` → `UnknownEvent::from_object` keeps `kind` + every other field verbatim (`:132-149`) and `to_object` (`:152-160`) puts the tag back first. Round-trip is byte-stable in content, pinned by `core/tests/events.rs:433`.
- `schema_version` rides on the envelope **only for unknown kinds** (`:210-215`, `:226-229`); a known kind's version is implied and read back as `unwrap_or(1)` (`:253`).

**Schema generation.** `core/src/schema.rs:50-52` (`schema_for!(StoredEvent)`, titled `yunta event`) → `schema::all()` → `xtask/src/main.rs:64-90` writes/`--check`s `crates/core/schemas/events.json`. `EventPayload`'s derived schema is a `oneOf` of 36 branches each pinning `kind` as a `const`.

**What must stay byte-identical if `EventPayload` were reorganised into per-domain sub-enums**

1. **The serialized object shape.** `serde_json::to_string(&payload)` is what lands in `events.payload_json` (`storage/src/store.rs:235-238`) and, via `render_events_jsonl` (`engine/src/events_export.rs:27-38`), in the archived `events.jsonl` — which `events_export.rs:8-11` declares *unmigratable once it leaves the system*. The object must stay flat: `kind` at top level, payload fields as siblings. Any two-level tagging breaks `EventBody::from_object` and every exported log.
2. **`kind_name()` output**, which is stored in its own `kind` column (`store.rs:272,286`) **and** hashed as the 5th field of the chain (`store.rs:65-96`, `:266-274`). `verify_chain` recomputes from the *stored* `payload_json` string (`store.rs:380`), so existing runs stay verifiable; but the writer must keep producing identical bytes or a resumed run's chain diverges from its own history mid-log.
3. **`EventPayload::KINDS`** — the sole arbiter of known-vs-unknown at `mod.rs:176`, and asserted equal to the schema's `oneOf` order at `schema_json.rs:88`.
4. **`$defs` names and nesting in `events.json`**: `Envelope`, `EventPayload` (a 36-branch `oneOf`), `GateResolvedPayload`, `RunId`, `Seq`. Sub-enums would introduce `$defs.FindingEvent` etc. and turn `EventPayload` into an `anyOf` of `oneOf`s — failing `schema_json.rs:87` and producing a large `events.json` diff. **That test compares against `EventPayload::KINDS`, so it would have to be rewritten, not merely regenerated** — the constraint is a design decision, not a mechanical one.

**Is a custom `Deserialize`/`JsonSchema` feasible?** Yes, and there are **two working precedents in this exact module**:

- `StoredEvent` already hand-writes all three (`mod.rs:217-280`), using `schemars::json_schema!` with `allOf` over `subschema_for::<Envelope>()` + `subschema_for::<EventPayload>()`.
- `GateResolvedPayload` already decouples the Rust shape from the wire shape entirely: `#[serde(from = "GateResolvedWire", into = "GateResolvedWire")]` (`payloads.rs:548-549`) with a private wire struct carrying `Serialize + Deserialize + JsonSchema`, and `From` impls at `:606-668`. The schema published is the wire's, not the enum's — asserted by `schema_json.rs:92-117`.

So a per-domain reorganisation keeping the flat wire is mechanically available: domain sub-enums for the Rust side, one `EventPayloadWire` (or a hand-written `Deserialize` dispatching on `kind`) plus a hand-written `JsonSchema` emitting the same 36-branch `oneOf` in the same order.

**D141.** `docs/design/adrs.md:151`: *"Antes del primer tag publicado, un payload de evento se reemplaza en el lugar … conservando `kind` y `schema_version`."* The precondition still holds — `git tag` is empty (0 tags; `Cargo.toml` at 0.0.4 is not a tag, and D141 says explicitly *"lo que fija la línea es el tag, no el número de versión"*). **Restructuring payloads today costs no `_v2` kind.** After the first tag, the same change costs 36 potential `_vN` siblings forever. This is the cheapest possible moment.

## 7. IDEAL — and what must survive untouched

### Keep exactly as they are (name them so nobody rebuilds them)

1. **`EventDraft` / `StoredEvent` split** (`mod.rs:37-54`). A draft carries no `seq` and no `timestamp`, so no caller can invent them; storage assigns both. This is "Núcleo puro" done right.
2. **`EventBody::Unknown` + `UnknownEvent`** (`mod.rs:96-199`) and the `unknown_kinds` chain through `replay.rs:92` → `stats.rs:274` / `view/mod.rs:218` / `receipt/mod.rs:253` → `cli/src/commands/mod.rs:271`. Verbatim round-trip, counted by name, never a break. Textbook "degradación explícita".
3. **Strict on known kinds, tolerant on unknown ones** (`mod.rs:176-182`): a known kind with wrong fields is `EventShapeError::Payload`, never silently demoted. This is "Parsear es validar" at the exact boundary CLAUDE.md names ("la tolerancia vive solo en lo persistido y versionado").
4. **`GateResolvedPayload`'s `from`/`into` wire indirection** (`payloads.rs:548-549,582-668`) — the Rust shape is the domain's, the wire shape is the format's, the mapping is decided once, and `Unrecognized` writes an unnamed combination back verbatim. **This is the template for the whole redesign.**
5. **`Failure`** (`failure.rs`) and **`Evidence`/`Fact`** (`evidence.rs`): failure and evidence as *data*, prose produced on read (`Display`, `Fact::line`, `Evidence::one_line`), with untagged back-compat for the pre-structural form. Never store prose.
6. **`FindingLedger` and `ArtifactLedger`** (`findings.rs`, `artifacts.rs`): total, pure, log-order folds with a named type and a documented ownership rule, plus `ArtifactLedger::apply` returning what it just held so `replay.rs:182-192` never names an artifact kind at all.
7. **`node_id` lives only in the envelope** (`spec-events.md:34-45`) — no payload repeats it.
8. **`RunLog`** (`run_log.rs`): one writer, one reader, one injected clock, with the observer mirror hanging off the single append (`:35-45`).
9. **`run_mode()`** (`mod.rs:329-334`): one function, documented as the single place mode is derived. Exactly the shape every other cross-cutting derivation should have.
10. **Schema generated from the types, committed, and CI-checked** (`schema.rs`, `xtask/src/main.rs:64-91`) + the hash chain over persisted bytes (`store.rs:60-96`), verified from stored bytes so read-side evolution can never invalidate an old run.
11. **The compile-time guard idiom** (`events.rs:279-326`) — a wildcard-free match whose only job is to fail compilation. Generalise it; don't delete it.

### Greenfield shape

**A kind is declared once, in the module that owns its domain.**

```
core/src/events/
  mod.rs          envelope, EventBody, StoredEvent (unchanged), the wire seam
  wire.rs         EventPayloadWire: flat {kind, ..} — the ONLY place the
                  36 snake_case names exist, derived from the domain enums
  run/            run_created, runner_resolved, baseline_captured,
                  run_paused/resumed/finished, promotion_signaled
  node/           node_started/finished/failed/rerouted, hook_executed,
                  context_assembled, criteria_checked, scope_checked
  session/        agent_session_opened, agent_message, capability_degraded
  tasks/          task_registered, task_status_changed, scope_expansion_*
  findings/       finding_posted/updated/withdrawn/refused  + FindingLedger
  artifacts/      artifact_accepted/submitted/written(read-only) + ArtifactLedger
  gates/          gate_waiting, gate_resolved, questions_answered
  children/       child_run_created/finished, loop_iteration
```

Each domain module owns: its variants, its payload structs **with their constructors**, its `kind_name` arms, and **its fold**. `payloads.rs`'s 989 lines dissolve into ~8 files of 80-150.

**The name exists once.** `kind_name`, `KINDS` and the schema branch are all derived from one declaration — a small `event_kinds!` macro, or a `Kind` trait with an associated `const NAME: &str` plus a `const KINDS` assembled from the domain enums. `KINDS` stops being a hand-typed list that only a test defends.

**Constructors enforce invariants.** `GateWaitingPayload::escalation(summary, evidence, options)` refusing an empty menu and refusing a summary that repeats an evidence value (`GateWaitingPayload::new` → `Result`, or a `NonEmpty<GateOption>` newtype so it cannot be expressed). `Degradation::new(capability, adapter, Policy)` with `policy_applied` a closed enum, not prose. `PauseReason` as a type with one variant per pause the engine has (`Escalation(GateWaitingPayload)`, `Cancelled`, `Budget{spent,cap}`, `ExternalGate(Url)`), rendering to a string once — so a reason can no longer be typed freehand. `TaskStatusChanged::done(task, caused_by, commit)` vs `::to(task, status, caused_by)`, making "only a `done` carries a commit" unrepresentable instead of conventional. Every one of these is the `Failure`/`NodeFailedPayload::new` pattern already in the repo, applied to the seven payloads that lack it.

**Readers cannot silently ignore a kind.** The wildcard is banned in state derivation. `replay::apply` matches per-domain: `match payload.domain() { Domain::Node(e) => node::apply(...), Domain::Tasks(e) => ... }` where each domain's `apply` is exhaustive over its own small enum — so a new finding kind fails `findings::apply`'s compile, and a new gate kind fails `gates::apply`'s, while the other six domains stay untouched. The "every other kind is bookkeeping" comment at `replay.rs:352-369` is replaced by a `Domain::Audit(_) => Ok(())` arm that a new kind must *opt into by name*. Presentation readers (`stats`, `view`, `live`, `receipt`, `cli`) may stay wildcard — they are lossy by nature — but each declares which domains it reads, so "no surface counts `capability_degraded`" is visible in a signature rather than in an audit.

**One fold per domain, and only one.** `FindingLedger` and `ArtifactLedger` already are it; `blackboard.rs` is corrected to consume `FindingLedger::of(...).effective_of(node)`. The missing ones get built where their domain lives: `TaskLedger` (status + `caused_by` + landing commit + registration identity + attempt count, replacing five scans), `GateLedger` (waiting/resolved pairing + `external_ref` + `approved_sha` + pre-seeded decision, replacing the two identical `last_external_ref` copies and four more scans), `NodeLedger` (attempts, terminals, open sessions, in-flight tokens, replacing 19 scattered folds), `SessionLedger`, `ChildLedger`, `DegradationLedger`. Each pure, total, log-ordered, `apply`-per-event, with the same doc sentence `FindingLedger` opens with: *a second fold is a second answer*.

**Docs derive, not duplicate.** The count in `mod.rs:282`, `events.rs:329` and `spec-events.md` §0 comes from `EventPayload::KINDS.len()`; the contract table row list is checked against `KINDS` by the same test that already checks the schema (`schema_json.rs:88`) — extended to read the markdown table, the way `xtask schema --check` reads the committed JSON.

**Do it before the first tag.** D141 (`adrs.md:151`) makes this free today — `git tag` is empty. After the first published tag the same reorganisation costs a `_v2` sibling per kind, in the log and in the published schema, forever.
